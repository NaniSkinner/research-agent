# Controlled Cedar results

Date: 2026-10-26. Scope: first two controlled stages only. Real-work runs paused.

## Result

Source accuracy was supported in the small fictional Cedar project, and the observed independent-review safeguards behaved as intended. Full Pstack workflow compliance and independently observable fresh-context configuration remain unestablished. This is not approval for a real-project run or general promotion.

Cedar Notes and Willow Orders are fictional fixtures, not people, products or production repositories. Only separate clean Cedar copies were investigated. Willow remains held out; PLC and C2.25 were not investigated or contacted in this round.

## Method and source of truth

The lead read the actual Cedar source before runs and set five criteria separately from candidate prompts: surrounding mechanisms, precise source support/unknowns, honest history/runtime boundaries, independent source review, and bounded useful output. The target code stayed clean at 17189f98ca3a01a5e4b2cfbe27782392826a5822.

The ordinary-role run and initial project-researcher run received the same natural research request except for the target copy's path. New contexts were explicitly requested; expected answers and other responses were not passed to the researchers. A separate fresh assessor saw anonymized answers and actual source without earlier verdicts. It found both accurate about the main mechanisms. No factual improvement over the ordinary agent is established by this one example.

Pstack Eval and Evidence First guided the lead's evaluation. This was a limited single-example control, not a full multi-model benchmark. Exact served model/effort and different-family grading were not established. Expectation separation was at the prompt/artifact level, not an adversarial filesystem security boundary.

## Remaining gaps

- The required visible Pstack Investigation throughput checkpoint was absent from the reports. Complete adherence to its how output/step requirements is not established by the supplied artifacts. Reading skills is not proof of completing them.
- Explicit Poteto initialization and sticky persistence were not established. Current-turn skill use must not be reported as trusted persistence.
- The revisit shows source reconciliation but does not establish a full instruction-resource reload. A normal follow-up is not necessarily a resumed or compacted session, so this does not prove a resume-rule violation; context recovery remains untested.
- Raw nested spawn arguments, resolved-role metadata and raw developer-injection traces are not exposed in these supported history records. Distinct workers and source reads are observed; do not upgrade them into complete proof of context isolation.
- Some Nessie operations were rejected by automatic approval review because broader name lookups could retrieve unrelated private material. Exact-name retrieval provided no relevant historical product evidence. History therefore remains unverified; no rejection was bypassed. Exa was unnecessary for these source-local questions and was not exercised.
- Existing-test assertion adequacy, cross-repository transfer, meaningful real history retrieval, parent-arranged review fallback, model-answer quality, runtime protections, moving revisions and compaction are not established by this small fixture.

## Disposition

Keep the narrow correction in 0.1.1. Do not infer a general reliability rate, full Pstack compliance, or superiority over a normal agent. Before promotion, a further controlled run should establish a visible selected-workflow receipt and initialization disclosure, with evidence or explicit limitations for each required step. Missing host metadata must stay unverified, not be filled in by a stronger prompt.

No real-work run is authorized by this result. Stop here for Nani's review. No Pstack files or hooks were changed. The Cedar staged and personal test profile match the corrected source; the unused Willow staged copy has not been refreshed or exercised in this round.
