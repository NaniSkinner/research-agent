# Selected-workflow evidence

Read the actual installed Pstack entry, runtime guidance, chosen playbook and applicable leaf skills. Copy the selected owner's named steps into the run's working note as that owner requires. Pstack owns the step list; this package must not freeze a competing list of skills or rubrics.

After explicitly reading the current canonical contract file and startup guidance, and before repository/history inspection or helper execution, publish a short startup receipt identifying the canonical contract path/version and selected workflow and its source/version or hash. Initialize from its runtime/portable guidance. Without a verified sticky receipt, state current-turn-only use and unverified persistence. Do not claim that invoking project-research activates sticky Poteto Mode.

Carry a compact receipt with every substantive report:

| Owner step | Applicability | Actual evidence or justified disposition |
| --- | --- | --- |
| Exact step from the selected installed workflow | Required or conditionally not applicable | Source/command/worker result and completion, blocked, or explicit skip |

A leaf skill's required delegation is not satisfied merely by reading its prompt or appointing the later reviewer. Use its configured role or documented portable fallback, within authority. If delegation is unavailable/prohibited, record the owner's allowed fallback or blocked step; never silently drop it. The independent research reviewer remains a separate fresh assignment.

Preserve the selected workflow's required report elements and checkpoint in the answer or linked run artifact. The short summary must not erase them. For example, if the installed Investigation workflow calls for a one-line read-only checkpoint and a how-shaped explanation, include those as that owner specifies alongside the evidence ledger. Inspect the current owner for exact text and applicable structure; this example does not replace it.

Preserve actual receipts and exact worker returns under references/evidence.md as the work proceeds. Give the reviewer the completed explanation artifact (or valid reused artifact), workflow receipt, original discovery/explanation outputs, evidence index and supported activity/operation exports before dispatch. Missing provenance stays reported-not-reverified; later self-authored receipts do not retroactively establish startup timing. The independent reviewer checks the complete answer and workflow receipt against actual sources and the selected owner's requirements. Reading an instruction is evidence of a read, not of executing its steps. Required unfinished steps keep workflow completion partial. Source findings can still be useful and returned with explicit limits.

On an ordinary follow-up, reconcile the current baseline and invalidation conditions. Actual resume after context loss or an instruction-version change requires reloading the contract and applicable resources. Do not invent a compaction event to satisfy a checklist, or claim resume behavior was exercised by a normal follow-up.

Receipt declarations and validator success do not prove semantic compliance. Use supported host records where available. A request for fork_turns none is not proof of host enforcement; preserve requested-only context evidence when confirmation is unavailable.

Maintain the compact prior-work map under prior-work.md across follow-ups. Include it as additional evidence in the fixed review packet, with decisive originals. Before proposing new research or testing, publish the closest prior outcome, remaining question/delta and bounded next action; short answers may use an inline record. The caller applies coordinator.md before dispatch and after return. This is an additional evidence checkpoint, not a new Pstack step list.

New delegated assignments follow startup.md: actual checklist/read/tool-interface evidence is checked by the parent before research-release. Retain the returned checkpoint, original reads and the parent release as workflow provenance. A later receipt cannot establish missing early ordering; a startup-only return is intermediate, not a substantive completed report.
