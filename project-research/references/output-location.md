# Target-owned research outputs

Before creating an output directory or capturing research evidence, resolve the destination from the target repository's actual guidance and the live assignment. The reusable agent checkout and the research target are different owners. A path in the caller brief is a candidate destination, not permission to publish.

## Discover the owning conventions

Read applicable AGENTS.md and its stated read order, the authoritative documentation map, track/story/sprint guidance and any relevant evidence/privacy/retention or publication policy. Resolve only relevant linked instructions; do not search excluded raw diagnostics to discover rules. Record exact guidance paths and revision, scope/story owner, output classification and limits. Do not assume a docs/ or artifacts/ directory is approved across repositories or branches. If a referenced story directory is missing at this checkout, reconcile the intended revision/owner rather than inventing a replacement or creating folders in someone else's checkout.

During startup this permits narrow routing/policy reads and read-only repository/path metadata only. It does not permit target implementation/history investigation or restricted-data access before research-release. The returned checkpoint must distinguish policy reads from research already performed.

## Choose by content and audience

- **Sanitized project findings or handoff:** use the active target's approved story/research documentation location and lifecycle. Keep repository-local links in team-facing docs. A proposed new document location is not an adopted convention. Respect owned-worktree/branch rules before writing tracked files.
- **Original evidence or restricted material:** use the applicable approved private evidence store and handling/retention contract. A private Git repository is not permission to commit raw diagnostics, user records, credentials, licensed content or protected cases. Copy only content authorized for this assignment; retention does not grant new access.
- **Generic reusable agent instructions and fabricated fixtures:** belong in the agent package. Never automatically place target-project reports, private source excerpts, connector records or real review packets in the reusable agent/source/installation checkout, even under an ignored folder.

Resolve symlinks and the nearest existing ancestors of a not-yet-created destination; check which Git repository, worktree, shared/synced location and audience actually own it. Do not infer visibility from a repository name, origin URL, absence of .git at the leaf, filename or gitignore. Use supported metadata when needed; if visibility/access controls are unavailable, preserve that uncertainty and do not publish. An ignored path is not access control. Do not fetch broad secrets or change permissions/sync settings just to claim privacy.

If no applicable private destination is established, ask the caller for the missing destination/handling decision. The caller should resolve known project guidance first and involve the user only for consequential unresolved choices. Do not fall back to the public agent package, an arbitrary target folder, a PR attachment, or /tmp for final evidence. Explicitly disposable tests/scratch may use temporary storage when authorized and labeled ephemeral; temporary output is not a durable handoff.

Record the chosen real path, content class, supporting policy/authority, intended audience/access evidence, repository visibility when relevant, lifecycle/retention owner and unknown controls. Reuse an existing output root only after this check. Restricted-data rules take precedence over general doc placement. Never create an _archive folder or delete historical evidence merely because another repo uses that lifecycle. Apply the target's actual lifecycle to the applicable artifact type; Git history can recover only committed material, not private untracked evidence.

## Caller and final reviewer

The coordinator checks output ownership at startup before release, including a misleading or symlinked caller-provided destination. No final research should rely on a public-agent directory or an unexplained temporary path. Keep report/evidence paths within the accepted output scope for workers. Explicit research permission is not commit, push, publication, access expansion or retention-extension authority.

The independent reviewer checks the report's source/policy locators and output classification, flags accidental private content in a tracked/public destination and preserves access-control/retention uncertainty. Return useful sanitized findings without embedding restricted raw values. The final answer links the authoritative report and its review receipt; do not create a duplicate executive report just to provide a stable entry point.

For existing packets in temporary storage, preserve the whole allowed bundle and verify bytes/packet identity at an approved durable destination. Keep originals/snapshots immutable, preserve expiry and provenance and update mutable entry links or document relocation separately. Moving does not authorize rewriting reviewed contents, replacing evidence with summaries, broadening access, committing the bundle, or deleting source material before verified retention and user authority permit it.
