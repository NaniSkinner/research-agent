# Default research-to-development handoff

When the user asks for a handoff, handoff doc, implementation handoff or a document for a new developing agent, this default applies. A short request is enough; do not require the user to list these parameters again. Honor narrower or different live instructions.

Before creating a handoff, apply output-location.md to the declared directory and target conventions. Create one concise standalone document in the accepted durable research output directory. If no destination exists, use an authorized task workspace or clarify the destination. Reuse existing research and original evidence; do not repeat the investigation merely to generate the handoff. Preserve original packets and reviews unchanged.

Include these sections. Mark absent information unknown/not established rather than inventing it:

1. **Purpose and boundaries:** repository, goal, relevant story, desired outcome, exclusions and current authority. Research completion is distinct from implementation or product readiness.
2. **Baseline and currentness:** exact inspected revision/worktree, relevant local changes, source dates and unverified current/remote/deployed state. The receiving agent must inspect current guidance and compare changed scope before planning, without blanket rediscovery.
3. **Implementation and evidence to reuse:** existing mechanisms, code/test locations, artifacts, checks actually performed, what they prove and limits. Distinguish source observations, historical outcomes, mocks and real generated behavior.
4. **Prior attempts and outcomes:** reusable successes, failed approaches and failure witnesses, what was not accepted and meaningful differences needed before repeating work. Use the prior-work map; missing history remains unverified.
5. **Remaining gaps, ownership and dependencies:** distinguish existing story scope, known capability gaps, unresolved behavior/product decisions and missing evidence. Preserve established ownership without inventing owners or duplicate stories.
6. **Decisions requiring user input:** exact open choices, consequences and conflicts. Keep unresolved matters unresolved; do not choose an architecture or convert assumptions into requirements. Preserve previously adopted decisions unless current evidence establishes a conflict.
7. **Bounded planning starting scope:** a candidate implementation slice, prerequisites, existing acceptance criteria and verification approach, plus criteria still needing agreement. This is a proposal for assessment, not an approved plan or authority to code. If no slice is supportable, identify the smallest decision needed first.
8. **Evidence and review limits:** link original research, prior-work map/claim ledger, decisive sources, original evidence and review artifacts. Preserve reviewed status, unresolved findings, provenance/freshness/context limits and checks not run; the handoff cannot upgrade them.
9. **Receiving-agent starting brief:** read the handoff and relevant current code/guidance; reuse findings; identify material changes since the reviewed revision; resolve open decisions with the user; then propose a bounded implementation plan. Do not begin coding, live checks or model runs unless separately authorized by the live user.

Verify consequential statements against existing sources and preserve their evidence level. Use the existing fresh independent review protocol for the substantive handoff, providing the actual handoff artifact and decisive sources. Record which artifact was reviewed. If review is unavailable, label the handoff draft and disclose the limitation; earlier report review does not automatically review this new document. New consequential factual claims require source checking and fresh review.

This request authorizes producing the document and returning its path. It does not authorize messaging another chat, creating chats, committing research to a product repository, implementation or starting another workflow. Pstack owns skill routing and selected workflow steps; this reference only defines this Research Agent's default handoff contents.
