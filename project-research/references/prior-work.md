# Prior-work checkpoint

Before calling something a new finding, gap, investigation or testing iteration, reconcile the closest relevant prior work through its recorded outcome. This applies to substantive reports, follow-up research and short clarification answers. A suggestion hidden in an example still counts as a proposed next step.

Maintain a compact prior-work map in the declared research artifacts. Each consequential proposal has these fields, in a row or short inline record:

| Candidate claim or next check | Classification | Closest prior evidence and outcome/limits | Remaining question and distinguishing delta | Smallest justified next evidence action |
| --- | --- | --- | --- | --- |
| Named behavior/path | One of the states below | Source locator, revision, assertions or observed result, disposition | Exact unanswered question; what changed or what earlier evidence did not cover | Reuse, retrieve, clarify or bounded proposed check within authority |

Use these classifications:

- **Established within scope:** cite and reuse the proved portion; preserve assertion, environment and revision limits. One accepted model answer does not prove reliable answers in general.
- **Previously attempted, unsuccessful:** preserve the failure witness and outcome. A further attempt needs a meaningful mechanism, input, environment or requirement difference and the question that difference would answer. Renaming fields or restating the same instruction is not a new mechanism.
- **Already planned or underway:** identify the existing story/owner/status; distinguish proposed work from implemented and accepted work. Return the unresolved portion to its existing scope rather than inventing a duplicate story.
- **Potentially outdated:** name the changed path, dependency, requirement or environment that could invalidate a specific earlier result. Reuse unaffected evidence and bound any revalidation to the changed portion.
- **Unresolved after scoped investigation:** state the unanswered question and sources/search scope actually inspected. An empty search is not proof that no prior work exists.
- **Prior evidence unavailable:** identify the known reference and exact missing outcome. Status is unverified, not never tested or genuinely new. Request recovery or clarification; any separately authorized repeat is a repeat under missing evidence, not historical proof.

Inspect relevant source/tests, existing research artifacts, linked plan/story records and primary history through resolution. Query Nessie under its installed contract for substantial research; record access/search limits. Check newer resolutions against stale handoffs, agent proposals against adopted decisions, and historical execution against current code. Resolve contradictory records explicitly; do not silently pick the most convenient one.

For ordinary follow-ups, reuse the map, verify the current baseline and inspect only the affected scope and new evidence. Re-open unresolved primary records when they could change the answer. A compact map is an index into evidence, not a substitute for source checking. Do not exhaustively reread the entire repo or repeat successful execution merely to fill this table.

Before any next-check recommendation, make the comparison visible: closest prior work → what it established or failed to establish → exact remaining question/delta → smallest justified next action. If no meaningful delta is established, reuse/recover evidence or ask a bounded clarification instead of selling the same test as new. If a changed path is uncovered, report that gap without blocking legitimate targeted verification. Recommendations do not expand execution authority.

Fresh independent review must challenge these classifications and comparisons, including consequential suggestions outside the claim ledger. Provide the map and decisive original evidence with the fixed packet. Missing comparison is a report defect to reconcile; unavailable history remains visible and does not require rerunning history. Pstack owns skill routing and selected workflow steps; this checkpoint adds an evidence obligation, not a replacement controller.
